1. What Is Fable?

Fable is a self-hosted digital library for organizing, reviewing, reading, and sharing access to books, comics, audiobooks, and physical-book records. The application and catalog run on your computer or server, while its browser interface lets permitted users work from other devices. Your files remain in storage locations you control rather than being moved to a third-party library service.

Choose a Supported Format

You can add books by uploading directly to a library, sending files through BookDrop for pre-import review, or placing files in a configured host folder and scanning its library. You can also catalog physical books without digital files. See Section 6: Books for the complete import and staging lifecycle and Section 7: BookDrop for the BookDrop workflow.

FormatDescription
PDFStandard document files (books, manuals, magazines)
EPUBCommon e-book format used by most e-readers
MOBI / AZW3Amazon Kindle e-book formats (MOBI, AZW, AZW3)
FB2FictionBook 2 XML-based e-book format
CBZ / CBR / CB7Comic book archives (ZIP, RAR, or 7-Zip image collections)
AudiobooksAudio files organized in folders (MP3, M4A, M4B, or OPUS)
PhysicalPrinted books or items in your real-world collection. Creating a physical book entry creates a catalog placeholder (no digital file required) so you can track your entire shelf in one interface.
Plan Ahead: A file must be allowed by the destination library as well as supported by Fable. Browser uploads also have a configured size limit, so check the library’s allowed formats and the upload limits in Section 6 before preparing a batch.

Choose Your First Task

  • Finish setup and add your first book: follow Section 2, then choose an import route in Section 6.
  • Separate collections by storage location or access: learn library boundaries and library tools in Section 5.
  • Review every new catalog entry before normal use: use the Staging lifecycle in Section 6.
  • Prepare filenames and metadata before import: use Section 7: BookDrop.
  • Organize books: use shelves and Magic Shelves in Section 8 and Section 9, or browse series and authors in Section 13.
  • Read or listen in a browser: open Section 10; bookmarks and notes are covered in Section 11.
  • Find books: use metadata search, filtering, or AI Search as described in Section 17.
  • Connect readers and other users: see OPDS, Kobo and KOReader sync, email, and accounts and profiles.

2. Getting Started — First-Time Setup

To access the Setup Wizard, open a web browser and navigate to your server's address and port—by default, http://<your-server-ip>:6060, or http://localhost:6060 from the host itself. The wizard appears only when Fable needs its first administrator account.

Create the First Administrator

  1. Enter the administrator’s display name.
  2. Choose a username.
  3. Optionally enter an email address.
  4. Create a password of at least 8 characters, confirm it, and finish setup.
Good to Know: The wizard creates only the first administrator. It does not create a library or configure local, OIDC, or Forward Auth login behavior. Configure libraries after signing in; account and authentication settings are covered in Section 22 and Section 23.
Be Careful: Choose a strong password. Anyone who knows this password has full control over Fable. There is no anonymous “Forgot Password” email reset by default. Another admin can issue a temporary password; if the sole admin loses every working local/OIDC login, stop and follow the supported recovery boundary in Section 22 rather than editing password hashes or improvising database commands.

Configure a Library After Sign-In

Create or open a library, then configure its storage directories. When Fable runs in a container, enter paths visible inside the container, such as /books, rather than an unmapped host path. The container-visible path must be backed by the intended host folder or mounted storage. See Section 5 for the canonical library and storage workflow.

Add and Check Your First Book

  1. Choose an import route. Use topbar Upload to send a browser file straight to a selected library path, use BookDrop when you want a review-and-finalize inbox, or copy a file into the library’s host folder and run Scan for New Files. The differences are explained in Section 6.
  2. Open HOME → Staging. Every newly created digital or physical catalog entry starts with staged=true. Confirm its title, author, cover, media type, and destination.
  3. Fetch or edit metadata if needed. A metadata fetch may finish automatically, produce a proposal in Review, or require a manual action. See the Staging lifecycle.
  4. Open the book. Verify that a digital file reads or plays correctly. Physical entries have no readable file by design.
  5. Release it from Staging. Select the book and choose Release. This only clears its staged status; it does not move the file or remove library, shelf, or metadata assignments.

Open Fable on a Second Device

On another computer, tablet, or phone that can reach the server, open http://<your-server-ip>:6060 and sign in. Use the server’s LAN hostname or IP address—localhost on the second device refers to that device, not the Fable server. Browser layout preferences can differ by device, while account-backed settings such as HOME shortcut visibility follow your account. If the page cannot connect, confirm that both devices can reach the same network and that port 6060 is exposed by the host.

Join an Existing Fable

If someone already runs Fable and invited you, you skip this Setup Wizard. Use the username and temporary password they sent you, sign in, change your password when asked, then open the User Guide from the sidebar. Details: Section 22 — If someone invited you to Fable.

3. The Dashboard — Your Home Screen

Sidebar HOME Dashboard

The Dashboard is the first screen you see after logging in. Use it to resume reading and to spot recent activity; use the task pages linked below when you need to import, review, organize, or maintain books.

Configure the Dashboard

  • See library statistics at a glance (total books, reading progress, and media breakdown)
  • Access recently added books, continue-reading shortcuts, and other quick-start content rows
  • Configure dashboard sections by hovering over the Dashboard option in the left sidebar and clicking the gear icon that appears. You can enable up to 20 horizontal rows (scrollers)—such as Continue Reading, Continue Listening, Recently Added, Discover Something New, Magic Shelf, and Currently Reading
  • Customize each row’s target library filter, width, and item count from 1 to 20, and lock the layout to prevent accidental drag-and-drop reordering
  • Add books to the optional Currently Reading row from a book’s More Actions → Currently Reading menu item to access them with a single click
  • Enjoy a fully responsive layout that automatically adapts grid widths when viewed on desktop, tablet, or mobile screens
  • Jump to any section of the app using the sidebar navigation
Good to Know: Dashboard and layout choices can be browser-specific, while account-backed preferences follow the signed-in account. Expect the same account to look different in another browser until that browser’s local layout is configured.

Open the Page for Your Task

  • New books waiting for attention: open HOME → Staging, then follow Section 6: Staging lifecycle.
  • Add files: compare direct Upload, host-folder scan, and BookDrop in Section 6; use Section 7 for BookDrop review and finalization.
  • Maintain a storage collection: open a library’s ellipsis menu and use the task inventory in Section 5.
  • Organize books: use Shelves, Magic Shelves, Series and Authors, or Story Arcs.
  • Search: use standard or AI-powered search as described in Section 17.

Know the Dashboard Limits

  • Place dashboard panels at arbitrary pixel positions outside the row-and-grid system

5. Libraries — Organizing Your Collection

Sidebar LIBRARIES section

A Library is a storage boundary: it connects one catalog collection to one or more configured host or mounted directories. Its paths, permitted media formats, access rules, naming pattern, metadata behavior, and maintenance operations apply to the books inside that boundary. A shelf can group books across libraries, but it does not change where their files are stored.

Choose the Right Organization Boundary

Use this chooser as the canonical guide for deciding between a library, shelf, Magic Shelf, Story Arc, or metadata browse view.

If your goal is…Use

A manual collection that can include books from several librariesShelf (Section 8)
A collection that updates from filter rulesMagic Shelf (Section 9)
A guided reading orderStory Arc (Section 14)

Good to Know: Additional user accounts usually get an automatic personal library under /books/_users/{id}/ when the admin creates the user (see Section 22). Know the Storage Limitations

  • Treat one folder as two independent storage boundaries; each configured folder should belong to one library
  • Manage files on remote cloud services directly — Fable reads from local or network-mounted folders
Be Careful:
  • Deleting a library removes the catalog entry, not the source files on disk. If you want to delete real book files, that happens through book-file deletion flows, not library removal.
  • Moving or renaming book files outside of Fable will cause them to appear missing. Always let Fable manage file movements.
  • Use maintenance operations intentionally. They are broader than the additive Scan for New Files action.
  • If your book folder is on a network drive, set DISK_TYPE=NETWORK in your environment configuration (the .env file). File-writing operations are limited on NETWORK storage; automatic metadata writes stay disabled, while manual sidecar backups remain available.
  • Check permissions before importing or reorganizing. The Fable process needs the required access to the mounted path, and write-dependent actions cannot succeed on a read-only or otherwise unwritable destination.
  • Check allowed formats per library. A format supported by Fable can still be rejected when it is not enabled for the destination library.

Browser uploads default to a maximum of 100 MB per file. An administrator can raise the configured limit, up to the hard maximum of 1024 MB per file.

Plan Ahead: Before uploading, confirm the destination library allows the format and that the selected directory is writable. Fable applies the library naming pattern at import. If the resolved destination name already exists, the collision must be resolved rather than silently overwriting the existing file.

Staging Lifecycle: Staged, Review, Done, Release

Sidebar HOME Staging

New digital imports and newly created physical-book records begin with staged=true. Staging is a triage flag, not a separate storage location: the book already belongs to its selected library. Use the tabs to decide what still needs attention.

Tab/actionMeaning and next step
StagedThe staged inbox: books that do not currently have a pending metadata proposal and are not classified as completed. Inspect the book, edit metadata, or start a metadata fetch. On desktop and tablet, an amber barcode badge means ISBN Discovery completed without finding a valid ISBN; a red warning badge means the ISBN check could not be completed. Hover either badge for the recorded reason and check time. Books without either badge have no recorded ISBN problem.
ReviewStaged books with fetched metadata proposals awaiting a decision. Open the metadata review, compare proposed and current values, then apply or reject as appropriate. Pending review wins over the other triage buckets while the book remains staged. Releasing a book removes it from all Staging triage tabs and counts; Release does not itself accept or reject the proposal.
DoneStaged books whose metadata fetch has completed or whose ISBN has been verified, with no pending review proposal. Check the result before release.
ReleaseSelect one or more books and click Release. This changes only staged from true to false. It does not move files, alter metadata, change library or shelf membership, or delete anything.
Suggested loop: import → open Staged → correct or fetch metadata → resolve Review items → check Done → select the books → Release.
Plan Ahead — Staging ISBN Work: ISBN providers have provider-specific request limits. Start with a small test batch, review the results before expanding the run, and reserve large batches for overnight processing. The Fable server must remain running until the batch finishes. Interrupted ISBN work does not resume automatically; restart it for the books that still need processing.

Browse with the Directory Explorer

Book browser toolbar folder toggle button (left side of the header bar)

Fable includes a Directory Explorer — a collapsible folder-tree panel that slides out from the left side of the book browser. It lets you filter the current view by the actual folders on disk inside your libraries, exactly as they are organized in your filesystem.

Why Use the Directory Explorer?

If you already organize your collection into folders on disk — for example /Comics/Marvel/, /Books/Fiction/, or /Audiobooks/Sci-Fi/ — the Directory Explorer mirrors that structure directly in Fable. You can browse your library the same way you browse files on your computer, with zero metadata setup required. It is also a great complement to shelves and filters: use folders for broad organization and shelves for cross-cutting collections.

Opening and Closing

  • Open: Click the folder toggle button in the book browser toolbar (visible when viewing All Books or any library). The panel slides out from the left.
  • Close: Click the close icon in the panel header, or click the folder toggle again.
  • Resize: Drag the right edge of the panel to adjust its width. Your preferred width is remembered across sessions.
  • Collapse the left sidebar: If you need more horizontal room, collapse the main left sidebar first using the sidebar toggle button in the topbar to give both the folder tree and the book covers more space.

What is a metadata sidecar file?
A sidecar file is a small metadata file saved on disk beside a book or in the designated physical-book location. It can preserve details such as title, author, description, and ratings for later import or rebuilding. Physical-book creation writes a sidecar for the placeholder.
Physical Shelf View: The Physical Books page draws a custom shelf rail under each visual row, creating a virtual bookshelf display that wraps correctly as your collection grows.

Know the Book Management Limits

  • Directly edit the book file contents (Fable is a reader and organizer, not an editor)
  • Move or rename folders from the directory explorer (it is a filtering tool, not a file manager)
Be Careful:

  • Bulk deleting books is powerful — double-check your selection before confirming.
  • Deleting the last file: If you delete the only readable file from a digital book record, Fable removes the empty catalog card. To keep a catalog entry without a file, create a Physical Book entry instead.

Topbar BookDrop

Good to Know: The global BookDrop is the shared/admin inbox inside the container (default /bookdrop, commonly mounted from a host folder such as ./bookdrop). Non-admin accounts use private inboxes under /books/_users/{id}/bookdrop/.

Review and Finalize

  1. Wait for detection or click Rescan, then open topbar BookDrop.
  2. Select pending files. Selection can cover the current page or all pages.
  3. Prepare metadata. Review fetched values, import selected metadata, bulk-edit fields, or extract metadata from filename patterns.
  4. Choose a destination. Assign a permitted library and subpath to every selected file; defaults can be applied to the selection.

Be Careful: Finalization applies the destination library’s naming pattern and moves the source file; it does not overwrite an existing destination silently. Resolve naming collisions before retrying. 17. Search and Filtering

Topbar search bar , or book browser filter sidebar

Global Search

Type in the search bar to find books across your collection by title, author name, or ISBN. Description text is not part of ordinary metadata search. The topbar search requests lightweight server results as you type; network latency and catalog size can still affect when results appear.

AI Search

Topbar AI Search sparkle icon, or Settings AI Settings AI Search

AI Search requires the AI feature to be enabled, its sidecar service to be running and reporting ready, and the needed models/providers to be configured. An embedding model is required to index and retrieve book content; an LLM is also required for workflows that generate answers, summaries, or other text. Each user owns a separate set of embeddings, so one user’s completed indexing does not make the same books searchable for another user. Supported source formats are EPUB, PDF, and CBX. See What Is Embedding? and Application Settings → AI Search & Embedding Tuning.

  • From Search Bars: Click the sparkly blue AI Search located inside the topbar or library search input fields to open the AI Search Dialog and submit your query.
  • From Book Cards: Look for the AIS badge on individual books in your library. Clicking this badge will open AI Search directly on that specific book, allowing you to ask questions about its contents, summarize it, or explore its themes.
  • Automatic Metadata Tagging: When a book is embedded for AI Search, the metadata tag "AIS" is automatically applied. This allows you to easily filter, search, or create Magic Shelves for books that have embeddings. The tag is automatically removed if the book's embeddings are deleted.

What Is Embedding?

Think of embedding as Fable reading a book and creating a searchable "index card" for it. Just like a library card catalog lets you find books by topic without reading every page, Fable's AI reads your book's text, converts it into a mathematical representation (called a vector), and stores it in a database. When you ask a question like "find books with dragons," Fable compares your question against all those index cards to find the best matches — even if the word "dragon" never appears in the title or author fields. This is what makes AI Search so powerful: it understands meaning, not just keywords.

AIS Badge Color States — The AIS badge on book cards changes appearance to tell you the embedding status at a glance:

  • AIS Cyan on black — Book is fully embedded and ready for AI Search. Click the badge to ask questions about this book.
  • AIS Grey on grey — Book is marked for embedding but hasn't been processed yet. The AI service will pick it up on the next scan. Not clickable.
  • AIS Orange on black — Book was embedded with a different AI model than the one currently configured. The embeddings are stale and the book needs to be re-embedded. Click to see which model was used.
Plan Ahead: Extraction, OCR where needed, chunking, and embedding can take substantial time and CPU, especially for large PDFs or comic archives. A marked badge means queued or awaiting processing, not that a completion time is guaranteed. Status can lag while the sidecar starts, downloads a model, processes another item, or reports an error; confirm the service is ready before troubleshooting a book.

Save to Notepad: When you find a useful AI response, click Add to Notepad to save the snippet for later. See Bookmarks, Annotations, and the Notebook for the wider note-review workflow.

Sparkle Button Status Indicators — The sparkle in the search bars uses color and animation to reflect the AI Search service state:

  • Solid cyan — Service is ready. Click to open AI Search.
  • Flashing orange (800ms grey↔orange) — Service is warming up / downloading the embedding model. Wait for initialization.
  • Flashing red (800ms grey↔red) — Last search returned an error or no results. Click the sparkle to dismiss and retry.
  • Solid red — AI Search service is unreachable or encountered a fatal error. Check container logs.
  • Flashing cyan (800ms grey↔cyan) — A search is currently in progress. Results will appear in the dialog when ready.

18. AI Comic Panel Detection

Settings AI tab AI Panel Detection section, or inside the CBX reader header AI menu

When a comic has AI panel detection data, a AIP badge appears on the book card overlay, similar to the AIS badge for AI Search.

AI panel detection is an optional, per-user feature that detects individual panels on comic pages for panel-by-panel reading. Another user’s scan data and completion state do not substitute for your own.

Before Scanning

  1. Open Settings → AI, enable AI Panel Detection, and wait for the sidecar status to report READY.
  2. Choose a narrow library, shelf, folder, or other book-browser path before selecting books. Confirm that the selected path contains the intended comics.
  3. Start with one short comic to estimate time, CPU/GPU demand, and stored panel-data growth on this server.

Scan Selected Comics

  1. Open a comic and use the reader’s AI action for that book, or select comics from the current browser path and launch the panel scan.
  2. The selected-path batch scans only books that are missing panel data. Existing panel data is skipped unless you explicitly delete it first.
  3. Books and their pages are processed sequentially. A large selection can therefore run for hours even when the progress indicator is moving normally.
  4. Watch topbar progress, but allow for delayed status updates while a page is actively being analyzed.

Manage Panel Data

  • Scan one comic or a selected set from the current path.
  • Delete panel data for specific comics before a deliberate re-scan.
  • View statistics such as scanned counts and stored panel-data size.
  • Reload the AI model if the sidecar stops responding.

Limits and Operational Caveats

  • Panel detection is for supported comic content, not arbitrary non-comic formats.
  • Detection is not guaranteed to be perfect; unusual layouts may produce missed, merged, or false panels.
  • Scanning consumes sustained compute, memory, temporary working space, and persistent storage for results.
  • Dismissing or losing a progress indicator does not prove that processing or cleanup has finished. Refresh status and inspect saved data before restarting a batch.
  • Cancellation and cleanup may be cooperative: an active page can finish before work stops, and partial data or temporary files may remain until cleanup completes.
Plan Ahead: Panel scanning is resource-intensive and sequential. Keep the server and AI sidecar running, verify free storage, and use selected-path, missing-only batches instead of an unbounded collection-wide run. Test cleanup and re-scan behavior on one comic before deleting broad sets of per-user panel data.

Set Up an OPDS Catalog and Credential

20. Kobo and KOReader Device Sync

Settings Devices tab

Choose a sharing route: use OPDS for catalog browsing and downloads, this Devices page for supported Kobo/KOReader progress integration, or Email for an attachment. Reading in Fable through a device browser uses the web reader and needs no device-sync setup; it is separate from native e-reader progress sync.

First Use: Kobo

  1. Ask an admin for Kobo Sync permission, then open Settings → Devices → Kobo Integration Configuration.
  2. Enable Kobo Sync. Copy the generated Kobo Sync Token and keep it private.
  3. Choose reading/finished thresholds, Auto-Add New Books to Kobo Shelf, and optional Two-Way Reading Progress Sync. Enabling sync creates the dedicated Kobo shelf; disabling sync warns that it will delete that shelf.
  4. Use the external-documentation link beside the Kobo heading for the device-side connection procedure. The current Fable UI supplies and regenerates the token but does not install or patch Kobo software for you.
  5. Add a small book to the Kobo shelf (or rely on auto-add), sync the Kobo, open the book, then confirm progress returns to Fable. Position mapping is best-effort and usually chapter-level.
Kobo shelf timing: Shelf membership is the server-side source for what Fable offers, but changes reach the device during a later Kobo sync rather than immediately. Auto-add applies when qualifying new books are added after the option is enabled; do not assume it retroactively fills the shelf. Add existing books explicitly, then run and complete a device sync.

Admins also see server-wide KEPUB conversion, hyphenation, CBX-to-EPUB conversion, image compression, and size-limit controls. These are conversion policy, not per-device credentials.

First Use: KOReader

  1. Ask an admin for KOReader Sync permission, then open Settings → Devices → KOReader Sync Configuration.
  2. Enter a KOReader username and a password of at least six characters, then click Save. The sync toggles remain unavailable until credentials are saved.
  3. Copy the displayed KOReader API Path, username, and password.
  4. Use the external-documentation link beside the KOReader heading to configure KOReader’s progress-sync service with those values. Fable does not configure the KOReader application remotely.
  5. Enable KOReader Sync. If desired, also enable Sync reading progress with Fable eBook Reader for bidirectional web-reader/KOReader updates.
  6. Open the same book in KOReader and Fable and verify a test progress update. Progress is approximate and may resolve at chapter rather than exact-location precision.
Timestamp conflicts: Bidirectional progress uses update timing to decide which state should prevail. Incorrect device time, timezone drift, delayed offline uploads, or nearly simultaneous updates can make an older position appear newer and overwrite the desired one. Keep clocks synchronized and test one direction at a time before enabling two-way sync broadly.

Optional: Send KOReader Progress to Hardcover

  1. Set up KOReader first. Hardcover integration reports KOReader progress; it is not a way to transfer book files.
  2. Open Settings → Devices → Hardcover Integration.
  3. Get your personal API key from the linked hardcover.app/account/api page, enter it, and leave the field to save it.
  4. Enable Sync KOReader Reading Progress to Hardcover, make a KOReader progress update, and verify it in Hardcover.

Hardcover reporting is dispatched asynchronously after a KOReader progress update. A KOReader/Fable sync can succeed even when the later Hardcover request fails. Failures are not placed in a durable retry queue, so verify important updates in Hardcover and trigger a later progress update to try again.

Supported Results and Boundaries

  • Kobo can sync shelf content and, when enabled, best-effort progress in both directions. The stored percentage and reading-status thresholds are useful summaries, not exact page, sentence, or cross-format location guarantees; conversion and chapter mapping reduce precision.
  • KOReader can sync progress through the displayed API endpoint; web-reader synchronization is a separate opt-in toggle. KOReader identifies a document by a hash derived from file content, not merely Fable’s title or database ID.
  • Metadata write-back, conversion, replacement, or another operation that changes file bytes can change that hash. KOReader may then treat the rewritten file as a different document, so previous progress may no longer match it. Finish or verify sync before rewriting files and retest identity afterward.
  • Hardcover receives KOReader progress only; it does not browse Fable or receive files.
  • Kindle has no direct device-sync integration; use OPDS where supported or email delivery.
Be Careful: Regenerating a Kobo token invalidates the old one. Keep device credentials and the Hardcover API key private. Test with one book before enabling automatic shelf additions, bidirectional progress, metadata write-back, or broad conversion settings.

23. Authentication — Login Methods

Local/OIDC: login page and Settings OIDC  |  Forward Auth: deployment environment and trusted reverse proxy

Fable supports three authentication paths: Local, OIDC, and environment-configured Forward Auth (called remote authentication in configuration). OIDC has an admin Settings page; Forward Auth does not.

Local Password

The default method — log in with your username and password. Simplest option for personal and multi-user use. Passwords are stored securely (hashed). Sessions use JWT tokens that auto-refresh.

When an admin creates an invited user, they can Copy all an invite pack that includes a login link (often with ?reason=invite), username, and temporary password. Open that link, sign in, then change the password when prompted. See Section 22.

OIDC (OpenID Connect)

Use a third-party identity provider (like PocketID, Keycloak, or Authentik) for single sign-on.

  1. Log in as an admin and open Settings → OIDC.
  2. Copy the values in Provider Configuration Reference into a new client at the identity provider: redirect URI, post-logout redirect URI, back-channel logout URI where supported, required scopes, PKCE method, and grant type.
  3. In Fable, enter Provider Name, Client ID, optional Client Secret for a confidential client, Issuer URI, scopes, and username/email/name/groups claim mappings.
  4. Click Test Connection, expand the checks, and resolve failures before saving and enabling OIDC.
  5. Choose provisioning, local-account linking, group mappings, default libraries/permissions, session duration, and any mobile redirect URIs your deployment needs.
  6. Test a non-admin login and an admin login in a private browser window before enabling OIDC-Only Mode.

OIDC provisioning: When auto-provisioning is enabled, a first login can create an account using the configured default permissions and default shared libraries. It does not create a personal library under /books/_users. Review the provisioned account in Settings → Users after first login.

Forward Auth (Reverse Proxy)

Forward Auth trusts identity headers supplied to Fable’s remote-login endpoint by an authentication-aware reverse proxy. Configure it in the deployment environment; there is no Settings UI for this mode.

Forward Auth provisioning: New remote users inherit the OIDC auto-provisioning defaults for non-admin permissions and shared-library IDs. A user in REMOTE_AUTH_ADMIN_GROUP is provisioned as Admin and mapped to all current libraries. Forward Auth does not create a personal library. If new-user creation is disabled, pre-create and map the account in Settings.

Be Careful: Forward Auth fully trusts the configured identity headers. Never let a client send them directly to Fable. The only proxy allowed to reach Fable must remove incoming copies and set fresh, verified values after authentication. Restrict direct network access, use HTTPS at the trusted edge, and test that spoofed headers from an unauthenticated client are stripped. Otherwise a client could impersonate another user or inject an admin group.
Be Careful:
  • Never expose Fable directly to the internet. Use HTTPS and a properly secured reverse proxy; Forward Auth additionally requires network isolation from untrusted clients.
  • OIDC requires exact URL and claim configuration. An incorrect issuer, redirect URI, client credential, scope, or username claim can prevent login or provisioning.
  • Local Login remains available to admins. In OIDC-Only Mode the supported admin entry point is /login?local=true; it still requires the valid local password.
  • Test before switching modes. Keep a working local admin session open until ordinary/admin OIDC or Forward Auth tests have succeeded, including denied, spoofed-header, and new-user cases.

Settings Effects and High-Impact Changes

Use this hub before transferring settings, running broad metadata jobs, or enabling persistence. A successful save means the setting was accepted; it does not prove that every downstream file, provider, or sidecar service completed successfully.

App Settings Export and Import

  • Export scope: the transfer file contains application-wide settings the current operator can manage. Email provider/recipient records are stored separately and are not included.
  • Secret redaction: nested fields named clientSecret, apiKey, or cookie are exported as null. Treat other configuration in the file as sensitive anyway.
  • Import effect: after the UI confirmation, recognized application settings are written immediately, one setting at a time; this is not a dry run or an all-or-nothing preview.
  • Redacted-secret hazard: importing an unchanged export can write those null values back and clear working credentials. Restore required secrets in the import file or re-enter them immediately afterward, then test OIDC, metadata providers, and AI endpoints.

Metadata Provider Limits

  • Providers do not share one throttle policy. ComicVine detects its rate-limit response, honors Retry-After when available, otherwise uses a cooldown, keeps the batch visible as paused, retries after reset, and checks for cancellation while waiting.
  • Hardcover increases its inter-request delay after throttling. Google Books reports rate limiting but does not provide ComicVine’s batch pause/resume behavior. Other providers can fail, retry, or limit independently.
  • Test a representative batch, avoid overlapping broad jobs, watch provider-specific messages, and do not assume that one provider’s recovery behavior applies to another. See the task advisory.

Metadata Persistence, Sidecars, and File Movement

  • Default guards: write-to-original is off. The UI defaults its size ceilings to 250 MB each for EPUB, PDF, and CBX and 1000 MB for audiobook files; oversized files are skipped rather than rewritten.
  • LOCAL storage only: embedded write-back, conversion, and automatic reorganization depend on DISK_TYPE=LOCAL. NETWORK mode disables automatic local writes/moves because non-atomic network operations can corrupt or lose data.
  • File and hash changes: embedded writes modify the source file and refresh Fable’s stored hash. Sidecar-on-update can also rewrite the adjacent sidecar and cover. Back up representative files and verify external sync/deduplication behavior first.
  • CBR/CB7 conversion: when configured or required by the available archive tooling, a metadata write can replace a CBR/CB7 path with CBZ and update Fable’s filename record. Confirm free space and downstream device compatibility.
  • Automatic move risk: Move files to library pattern can rename or relocate files after metadata changes. Validate naming patterns and permissions on a small disposable set before enabling it broadly.
  • Automatic sidecars: standard digital-book sidecars are written beside the primary book as <base-name>.metadata.json (and optionally <base-name>.cover.jpg). Fileless physical-book sidecars are written at the library directory as <generated-name>.physical.metadata.json.
  • Manual backup location: run on-demand per-library sidecar backup from Settings → Backups → Sidecar. It writes/refreshes sidecars beside each supported book; it does not create a separate central backup archive.
Be Careful: The UI warns that embedding provider/model or structure changes invalidate existing embeddings, then the save takes effect immediately. This is a warning, not a separate confirmation gate. Fable marks affected books for re-embedding and clears incompatible embedding data. Configuration is pushed asynchronously to the AI sidecar after the database save, with a short delay and up to three attempts; a sidecar delivery failure does not roll back the saved setting. Check service status and retry/reload as needed.

Search Tuning Parameters

Settings AI AI Search Engine Search Tuning

These sliders control how the AI Search retrieves and presents results. Each has a range slider with −/+ stepper buttons and a direct numeric input:

  • Top K (1–50, default 5): How many context chunks to retrieve from the vector database. More chunks give the LLM richer context but increase processing time.
  • Display Top K (1–50, default 1): How many raw results to show in the UI. Set this lower than Top K to give the LLM more context while showing only the best match to the user.
  • Similarity Threshold (0.10–0.90, default 0.30): Minimum relevance score for a chunk to be included. Lower values return more results (some may be less relevant); higher values are stricter.
  • Max Tokens (128–4096, default 768): Maximum length of the LLM’s generated summary. Higher values produce longer answers but take more time and memory.
  • Temperature (0.0–1.0, default 0.1): Controls randomness in the LLM output. 0.0 gives deterministic, focused answers. Higher values (0.5+) produce more creative and varied responses.

RAG Techniques

Settings AI AI Search Engine RAG Techniques

Retrieval-Augmented Generation (RAG) techniques enhance answer quality by adding processing steps between retrieval and response generation. Each technique has an independent toggle switch. Features that add LLM calls are automatically disabled when using a local LLM provider to avoid excessive latency on CPU-only hardware. They activate automatically when using an external (cloud) LLM.

  • HyDE (Hypothetical Document Embeddings): Generates a synthetic ideal answer to your query, then uses that to find similar content. Especially effective for abstract or conceptual queries. Adds 1 LLM call.
  • Multi-Query Retrieval: Expands your single query into multiple variant queries and fuses the results for broader coverage. Adds 1 LLM call + N retrievals.
  • Query Decomposition: Breaks complex questions into simpler sub-questions, answers each one, then synthesizes a complete response. Adds 1 LLM call + N retrievals.
  • Self-Reflection: After generating an initial answer, the LLM critiques its own response and regenerates if issues are found. Adds 1–2 LLM calls.
  • Contextual Compression: Filters retrieved chunks to only the most relevant sentences before they reach the LLM, keeping responses focused. No LLM calls — works with any provider.

OCR Settings

Settings AI AI Search Engine Automatic OCR Fallback

Optical Character Recognition (OCR) extracts text from scanned or image-only PDF pages during book embedding:

  • Enable OCR — Master toggle. When on, Fable runs OCR on pages that have no extractable text layer.
  • OCR Fallback Only — When enabled, OCR only runs on pages where no text could be extracted normally. This avoids unnecessary OCR processing on pages that already have text.

Advanced Embedding & Retrieval Tuning

Settings AI AI Search Engine Advanced Embedding & Retrieval Tuning (click to expand)

This collapsible section (orange header, collapsed by default) contains low-level tuning parameters for the embedding and retrieval pipeline. It includes an Auto-Fill Recommended Presets button that loads optimal settings for your currently selected embedding model.

Be Careful: Modifying Chunk Size, Chunk Overlap, Semantic Chunking, or Matryoshka Dimensions changes how embeddings are structured. The UI warning precedes an immediate save; saving automatically deletes incompatible existing book embeddings and marks affected books to be re-embedded. It is not a separate confirmation step. Search-only parameters (Hybrid Search or Reranking) do not invalidate existing embeddings.
  • Chunk Size (500–8000, default 1500): Maximum characters per text chunk during embedding. Larger chunks preserve more context but reduce search precision. Models with wide context windows (like Nomic at 8k) benefit from larger values.
  • Chunk Overlap (0–1000, default 100): How many characters overlap between consecutive chunks. Prevents key sentences from being cut at chunk boundaries.
  • Semantic Chunking: Toggle + threshold slider (0.10–0.50). When enabled, Fable splits books at natural text boundaries (paragraphs, sections) rather than at fixed character counts. The threshold controls how aggressively it detects boundaries — lower values create more chunks.
  • Matryoshka Dimensions: Dropdown (Disabled / 768 / 512 / 256 / 128). Supported by advanced models like Nomic, MRL allows slicing high-dimensional vectors down to fewer dimensions with almost no impact on retrieval accuracy. Slicing vectors and re-normalizing them speeds up cosine similarity comparisons on CPU by up to 3×, saving significant memory.
  • Hybrid Keyword Search (BM25 + Vector): Toggle + RRF K slider (10–200, default 60). Combines semantic vector similarity with traditional BM25 exact keyword matching using Reciprocal Rank Fusion. Highly effective at finding specific names, numbers, or technical codes that vector models might overlook.
  • Cross-Encoder Reranking: Toggle + model selector dropdown. Runs a lightweight cross-encoder model (such as BAAI/bge-reranker-base) in a background thread. While standard bi-encoders retrieve candidate chunks quickly, a cross-encoder evaluates the exact match relation between the query and text for the top candidates. This brings GPU-grade search precision to CPU hardware in milliseconds because it only reranks a handful of candidates instead of the whole database.

Routine Backup Procedure

  1. Prepare encrypted off-host storage. Keep the recovery copy on a different machine/account or immutable backup target, encrypt it at rest and in transit, restrict access, and record the Fable/MariaDB version and deployment paths. A second folder on the same disk is not off-host protection.
  2. Coordinate a recovery point. For a consistent set, pause or tightly coordinate catalog writes, scans, imports, scheduled tasks, and database export timing so the SQL dump, app data, and media represent the same recovery window.
  3. Export app settings. Open Backups → App Settings, click Export, and store the downloaded JSON securely. It excludes email records and redacts fields named clientSecret, apiKey, and cookie; it is not a secret, database, or media backup.
  4. Optionally write sidecars. Open Backups → Sidecar, select one library, click Back Up Sidecars per Library, and verify attempted equals exported with zero failed. Repeat for each required library.
  5. Prepare a logical database dump. As an admin, open Backups → Database Export, set the destination directory and filename, review the generated command for your deployment, and click Copy export command.
  6. Run the copied command outside Fable in the documented host/container environment. The UI only records that the command was copied; independently verify a non-empty SQL file was created.
  7. Copy companion data. Back up all library media, the mounted Fable app-data directory, and deployment configuration/path-mapping notes. Include BookDrop content if pending files matter to recovery.
  8. Validate the set. Confirm the SQL dump, app-settings JSON, media, app data, and deployment notes are readable from the off-host destination, then record checksums, sizes, date, version, encryption/recovery-key location, and retention expiry.
  9. Test restore regularly. Restore a copy into an isolated non-production environment, run the outcome checks below, document elapsed time and corrections, then remove the test environment securely. A backup is not proven until a restore test succeeds.
Good to Know: App Settings JSON covers application configuration only. Sidecars preserve supported per-book metadata only. The logical SQL dump protects catalog/database state but not the media or app-data files. A recoverable set therefore needs the database dump plus matching media, app data, and deployment information.

Safe Restore Ordering

  1. Do not overwrite the only good copy. Preserve the incoming backup set and take a fresh backup of the current target before starting.
  2. Match the environment. Recreate or verify deployment configuration, mounts, service names, path mappings, and a compatible Fable/MariaDB version.
  3. Stage files first. Put library media and app data at the confirmed target paths with appropriate ownership and enough free space.
  4. Pause writes. Stop or isolate scans, uploads, BookDrop processing, metadata edits, scheduled tasks, and user traffic across every Fable instance that can reach the data. The UI’s maintenance checkbox is an operator confirmation; it does not pause the system for you.
  5. Run the UI preflight. Open Backups → Database Restore; enter the SQL path, app-data path, deployment-config path, and measured free space. Confirm the SQL/notes, media, app data, config, version, and maintenance plan. The UI only checks that the entered free-space value is at least 15 GB; 15 GB is not a sizing recommendation and can be far below what your database, app data, temporary restore work, and media require.
  6. Resolve every failed check. Only after all checks pass should Copy restore command become available. The helper supports restoring into the existing fable schema; a temporary-schema restore is outside the current grants/UI boundary.
  7. Review and execute externally. Inspect the copied command against the actual service/container name and credential handling, then run it in the documented operator environment. Fable does not execute or verify that command.
  8. Start and validate. Bring services back in controlled order, wait for health checks/migrations, then validate login, user/library mappings, book counts, representative metadata, covers, reading progress, annotations, shelves, BookDrop, and one reader download before reopening writes.
  9. Retain rollback material. Keep the pre-restore target backup and original recovery set until validation and a subsequent fresh backup both succeed.

Restore Outcome Checks

  • Authenticate through every enabled method, including a local break-glass admin; review authentication boundaries.
  • Compare expected users, permissions, personal/shared library mappings, library/book/file counts, and representative audit/task history.
  • Open representative EPUB, PDF, CBX, and audiobook files; verify covers, metadata, shelves, reading progress, bookmarks/annotations, OPDS/download access, and one device integration where used.
  • Re-enter and test secrets omitted or nulled by settings transfer, including OIDC/provider/API credentials and separate email records; see Settings Effects.
  • Run a small additive scan and one reversible metadata update, confirm sidecar/file behavior, then take a fresh post-restore backup before reopening normal writes.
